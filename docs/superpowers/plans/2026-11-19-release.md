# Release Publishing Implementation Plan

> For agentic workers: use superpowers:executing-plans for root integration and superpowers:dispatching-parallel-agents for independent providers, then independent code review.

Goal: complete release UI and reusable post drafts with actual YouTube/Instagram upload clients.
Architecture: publishing package separates pure models, encrypted storage, OAuth/provider clients, media preparation and batch orchestration; two focused dialogs handle account setup and release. Existing render pipeline only exposes its finished file.
Tech: existing Python/PySide6/requests/FFmpeg and stdlib; no new dependencies.
Spec: docs/superpowers/specs/2026-11-19-release-design.md

## Constraints
Preserve uncommitted title/order features. Never publish, log credentials, read actual user settings/projects, create accounts, or use user tokens during verification. No commits/push. Settings draft contains only post preferences; credentials/state are encrypted. User's current instruction authorizes implementation of the flow already discussed; routine defaults do not need another approval round.

## Review focus
Cancellation at final request and dialog closure; ambiguous writes and partial success; expired credentials and state corruption; draft persistence on cancel/X/reopen; actual file/media eligibility and source preservation.

## Shared interfaces (root provides before provider work)
- publishing.models.ReleaseDraft(title='',body='',youtube=True,instagram=True,privacy='public',made_for_kids=False,video_path='',instagram_video_url=''), from_dict/to_dict; PublishedPost(platform,id,url,already_uploaded=False); PublishError; PublishUncertain; noop(stage,done,total,message); check_cancel(cancel).
- publishing.credentials.CredentialStore(path=None,protect=None,unprotect=None): get(section)->dict, put(section,dict), delete(section). Thread-safe atomic DPAPI JSON, default config_dir()/publish-secrets.bin. Tests can inject byte codecs.
- ProgressFn standard(stage,done,total,message); providers report target stage fractions and no secret values.
- Provider state is a mutable dict with save_state(dict) callback. Root persists whole provider state encrypted under operation key; success record fields status/id/url. Session URLs/tokens never enter plain settings/history.

## Final verification

- Full offline suite: **678 passed, 3 network tests deselected** in69.71s; mocked provider APIs, real Windows DPAPI dummy-data roundtrip, real two-process receipt preservation, synthetic FFmpeg compatibility/source preservation and GUI tests included.
- Offline UI screenshots verified Korean body/hashtags and saved source-bound URL on reopen; original YouTube source and Instagram derivative remain separate.
- One independent whole-feature review: nine Important findings fixed with observed RED→GREEN regressions, then full suite green. Cancellation/final requests, URL/derivative identity, source replacement, interprocess state, malformed uncertainty, close-on-save-failure and confirmed receipt-save failures covered.
- Deferred minor: an earlier ambiguous Instagram container answering PUBLISHED without its media ID still displays status-unknown; duplicate protection remains in place. No blind repost.
- Ruling carried from execution: independent provider modules were implemented in parallel and integrated inline, with one final whole-feature review rather than per-task reviewers. Disjoint ownership/fixed contracts justified the choice; cost if wrong was integration rework.
- Actual account connection/publication was not performed. User supplies provider account configuration via the app. Keep changes on the current feature checkout; no commit/push for this task.
